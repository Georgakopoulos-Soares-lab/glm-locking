# Setup on a New Cluster

This documents everything needed to go from `git clone` to running experiments.
Tested on TACC LS6 (H100 nodes) and NVIDIA DGX (A100 nodes).

## 0. Quick start (~10 min)

```bash
git clone https://github.com/Georgakopoulos-Soares-lab/glm-locking
cd glm-locking
bash setup_evo_env.sh          # creates 'evo' conda env
conda activate evo
```

**Verify**: `python3 -c "from evo import Evo; print('OK')"` must succeed.

## 1. Disk space requirements

| Item | Size | Notes |
|:---|---:|:---|
| Evo-1-8k-base model | ~28 GB | Downloaded once to HF cache |
| attack.fasta | ~38 MB | Downloaded via script |
| retain.fasta | ~131 MB | Downloaded via script |
| ViroBench data | ~8.2 GB | For Priority 5 eval |
| Lock checkpoint (α=10⁵) | ~16 GB | Generated, store on large disk |
| Lock checkpoint (α=3×10⁵) | ~16 GB | Generated, store on large disk |
| Training outputs (per run) | ~200 GB | Checkpoints every 2000 steps × 15+ |

**Total**: ~100 GB base + ~200 GB per experiment. Use a filesystem with **no quota** (e.g. `/scratch` on LS6).

### Set HF_HOME to a large disk

```bash
export HF_HOME=/scratch/$USER/hf_cache   # or /data/nvidia/... on DGX
```

On LS6, `/home` fills up immediately. Always point `HF_HOME` elsewhere.

### Symlink results to a large disk

```bash
# On LS6 (1TB user quota on /work):
mkdir -p /scratch/$USER/evo-locking/results
ln -sf /scratch/$USER/evo-locking/results results

# On DGX (no quota on /data):
mkdir -p /data/nvidia/evo-locking/results
ln -sf /data/nvidia/evo-locking/results results
```

## 2. Files: what's in the repo vs what you must generate

### ✅ In the repo (git clone gives you these)

| Path | Description |
|:---|:---|
| `configs/lock/*.yaml` | Lock configs for α=10⁴, 3×10⁴, 10⁵, 3×10⁵ |
| `configs/finetune/*.yaml` | All fine-tuning configs (A–N, seed replicates) |
| `scripts/*.py`, `scripts/*.sh` | All pipeline scripts |
| `experiments/split_manifest/*.txt` | Accession lists for clean three-way split |
| `data/download_scripts/*.sh` | Scripts to download attack & retain FASTAs |

### 🔧 Must be generated on each new cluster

| File | How to generate | Time |
|:---|:---|:---|
| `data/attack.fasta` | `bash data/download_scripts/download_attack.sh` | ~1 min |
| `data/retain.fasta` | `bash data/download_scripts/prepare_retain.sh` | ~5 min |
| `data/attack_train.fasta` | `python scripts/split_attack_fasta.py` | <1 sec |
| `data/attack_heldout.fasta` | (generated by above) | |
| `results/lock_alpha*/model_specdef.pt` | `python scripts/lock_specdef.py --config configs/lock/alphaXXXk.yaml` | ~5 min each |
| `results/ft_*/` (training outputs) | `bash scripts/run_pipeline.sh <GPU> <config>` | ~31h per run |
| Evo model cache | Auto-downloaded on first `load_evo_model()` call | ~10 min |

### Step-by-step: generate all prerequisites

```bash
# 1. Download data
bash data/download_scripts/download_attack.sh
bash data/download_scripts/prepare_retain.sh

# 2. Split into train/heldout
python scripts/split_attack_fasta.py

# 3. Generate lock checkpoints (fast, ~5 min each on GPU)
for alpha in 10k 30k 100k 300k; do
  CUDA_VISIBLE_DEVICES=0 python -u scripts/lock_specdef.py \
    --config configs/lock/alpha${alpha}.yaml
done
```

## 3. Running experiments

### Single experiment (31h)
```bash
bash scripts/run_pipeline.sh 0 configs/finetune/locked_a300k_lr1e5_25k.yaml
```

### Parallel experiments (tmux recommended)
```bash
tmux new-session -d -s evo -n K  "bash scripts/run_pipeline.sh 0 configs/finetune/locked_a100k_lr1e5_25k_seed2.yaml 2>&1 | tee logs/runs/K.log"
tmux new-window  -t evo -n M  "bash scripts/run_pipeline.sh 1 configs/finetune/locked_a300k_lr1e5_25k_seed2.yaml 2>&1 | tee logs/runs/M.log"
tmux attach -t evo
```

## 4. Priority ordering (from ROADMAP.md)

| Priority | Experiment | GPU-hours | Config |
|:---|:---|---:|:---|
| 1 | SVD α=10⁵ checkpoint eval | ~2h | (eval only, no training) |
| 2 | Unlocked full-910 eval | ~2h | (eval only) |
| **3** | **M seed replicate** | **~31h** | `locked_a300k_lr1e5_25k_seed2.yaml` |
| 4a | C′ seed replicate | ~31h | `locked_a30k_lr1e5_25k_seed2.yaml` |
| 4b | K seed replicate | ~31h | `locked_a100k_lr1e5_25k_seed2.yaml` |
| 4c | I (SVD k=3) seed replicate | ~55h | `theorem8_a30k_k3_25k_seed2.yaml` |
| 5 | 10k-genome stress test | ~62h | See ROADMAP §6 |

## 5. Cluster-specific gotchas

### LS6 (Stampede3)
- **Quota**: 1TB on `/work`. Use `/scratch` for results and HF cache.
- **Python path**: `run_pipeline.sh` auto-detects the evo env now.
- **TMPDIR**: Set to `/scratch/$USER/tmp` (avoids `/tmp` on small root fs).

### DGX (original cluster)
- **Python path**: `/home/nvidia/miniconda3/envs/evo/bin/python`
- **Results**: `/data/nvidia/evo-locking/results` (symlink `results/` → there)
- **GPU**: A100 80GB. SVD k=5 requires full 80GB.

## 6. Verifying a fresh setup

```bash
# 1. Conda env
conda run -n evo python -c "from evo import Evo; print('OK')"

# 2. Data files exist
ls -lh data/attack.fasta data/retain.fasta data/attack_train.fasta data/attack_heldout.fasta

# 3. Lock checkpoints exist
ls -lh results/lock_alpha100k/model_specdef.pt results/lock_alpha300k/model_specdef.pt

# 4. HF model downloads correctly
CUDA_VISIBLE_DEVICES=0 python -c "
from src.utils import load_evo_model
m, t = load_evo_model('evo-1-8k-base', 'cuda:0')
print(f'Model loaded: {sum(p.numel() for p in m.parameters()):,} params')
"
```
